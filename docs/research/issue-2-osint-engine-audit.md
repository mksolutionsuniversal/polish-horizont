# Issue #2 — OSINT engine candidate audit

**Observed:** 2026-10-20 (GitHub public repository/API views).  
**Method:** read-only inspection of upstream GitHub metadata and selected tracked files. No clone, install, build, code execution, API calls to either candidate, or service deployment was performed.  
**Decision status:** candidates only; this audit does not approve a dependency or authorize integration.

## Executive summary

For a narrow public-news ingestion experiment, `cyanheads/gdelt-mcp-server` is the better scoped candidate to investigate next: its declared purpose is GDELT DOC article search/analysis plus US television transcripts, and its published package metadata exposes nine tools. It still needs a source-policy, coverage, provenance and implementation review before adoption. “Free/public API” is not evidence of permission to republish every returned article or transcript.

`marc-shade/world-intel-mcp` is a much broader intelligence platform (README claims 160 tools across 30+ domains and 119 RSS feeds). Its news functions could be useful as a comparator, but its footprint and multiple stateful/collection features are disproportionate for a first news-only module. The README and repository metadata are not sufficient to establish that every tool is read-only.

Neither candidate is approved by this document. HORIZONT’s public README describes the project as early planning, with no deployed application, and says no open-source license has yet been granted to this repository.

## Security, legal and data-quality findings

- **Least privilege:** neither candidate has been approved for integration. If pursued, expose a small HORIZONT-owned adapter with only selected query operations; do not expose a broad third-party tool registry by default. For `world-intel-mcp`, inspect every proposed tool before allowing it because documented server capabilities include state changes and collection/backfill operations.
- **Network boundary:** treat each server as an outbound network client. Before any later execution, produce an allowlist of exact hosts and redirects for the selected news operations, apply timeouts/rate limits, and test failure behavior. This audit did not send requests to candidate APIs.
- **Credentials:** no credentials were supplied to either candidate during this review. Confirm which operations are genuinely keyless from source and current upstream terms before design; do not store secrets in the public repository or fixtures.
- **Content rights:** public availability and no-cost access do not grant blanket rights to copy, retain, translate, republish, or derive commercial products from publisher content. Review GDELT and each publisher/source’s applicable terms, attribution requirements, copyright/database rights, retention limits and UK/EU obligations with the intended use in view. This is an engineering screening, not a legal opinion.
- **Provenance:** store source/publisher, canonical URL, provider query/window, language/region if supplied, retrieval time (UTC), event/publication time separately when available, and transformation/deduplication history. Preserve uncertainty and distinguish missing timestamps from zero/unknown values.
- **Data quality:** validate date/time zones, language and geography labels, duplicate/syndicated stories, stale or revised records, empty-result meaning, and whether returned text is an excerpt or full article. Do not infer that GDELT coverage is complete or representative for UK/PL.
- **Security posture:** repository LICENSE and SECURITY.md presence were checked for `world-intel-mcp`; the `gdelt-mcp-server` root has a LICENSE, while a root SECURITY.md was not found (404 at the observed ref). This is not a vulnerability assessment. Review dependency lockfiles, advisories, authentication defaults, logging and input/output handling at a pinned commit before use.

## Recommendation / next gates

1. Keep both repositories as unapproved research candidates. Prefer a narrowly scoped GDELT DOC-only prototype for the next *design* step, subject to explicit source rights and UK/PL coverage checks; omit TV endpoints unless there is a separate requirement.
2. Pin an immutable reviewed commit and enumerate the exact tool functions, outbound hosts, fields, dependency tree, license notices and update policy. Review transitive dependencies and any package lifecycle behavior before installing anything.
3. Run a documented, non-production coverage evaluation only after approval: representative UK, PL and global queries with a fixed time window; measure precision, recall proxies, language/geography accuracy, deduplication, freshness and provenance completeness against manually selected public references.
4. Decide permitted fields, retention, attribution and deletion handling before storing or displaying returned content. Keep HORIZONT’s occurred, published and collected timestamps distinct.
5. Reassess whether a direct, small GDELT API adapter is simpler and safer than adding an MCP server dependency.
